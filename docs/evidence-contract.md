# Evidence schema and truth policy

Schema `1.1`: `repo`, `readme_sha256`, `source`, `policy`, `policy_sha256`, `run`, `image`, `execution`, `steps[]`, `results[]`, `verdict`, `limitations`. `source`: full Git commit, selected tree/scope, clean flag, sorted path/mode/size/content-hash manifest and aggregate `source_sha256`. `run`: UUID, controller state/history and `plan_sha256`. `results`: `id`, `command`, `exit_code`, `stdout`, `stderr`, `outcome`, `duration_ms`. See `source-capture.md` for canonical hashing. Schema 1.0 passports are deliberately rejected.

PASS results must match the ordered step IDs/commands and have integer zero exit codes. Incomplete coverage cannot pass; an observed valid failure remains FAIL even if later steps were not run. BLOCKED runs cannot contain execution results. Missing Docker produces BLOCKED state, no results and INCONCLUSIVE verdict. Passport validation remeasures the complete current source/commit and policy and checks legal finalized history and consistent results. This establishes internal consistency and source binding, not signed execution proof; synthetic unit results are never reported as Docker success.

**Before submission extend:** resolved Docker image digest, runner version, per-step start/end UTC, reason codes and independent expected outcomes, bounded log hashes and redacted excerpts, attempt count, patch path hashes and clean-retest flag, model metadata and provider opt-in, agent A/B trial manifest, authenticated final evidence manifest. Export JSON and Markdown. Separate files under unique run IDs, atomic writes, no mutation after FINALIZED. Phase 1 records terminal states only; durable intermediate/crashed-attempt journaling remains unimplemented.

No model may edit a final evidence record, decide that failing steps "probably passed", or conceal skipped checks. `BLOCKED` before run is not equivalent to `FAIL` from the target. Clearly label unknowns, environment mismatch and flaky results.

**Success claim levels:** single-command `SMOKE_PASS`, documented setup `ONBOARDING_PASS` (all declared steps in stateful fresh env and explicit test), `AGENT_COLD_START_PASS` (independent agent executes fixed task), `GENERAL_REPRODUCIBLE` never claimed in MVP.
