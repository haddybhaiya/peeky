# Evidence schema and truth policy

Schema `1.2`: `repo`, `readme_sha256`, `source`, `policy`, `policy_sha256`, `run`, `image`, `image_digest`, `execution`, `coverage`, `steps[]`, `results[]`, `verdict`, `limitations` and controller `integrity` after storage. Source/policy/plan identity retains the Phase 1 canonical hashing contract. Execution is `offline-docker-single-command`. Legacy passport schemas must be rerun.

Each result contains ordered step ID/command, observed target exit code (absent when no target exit was observed), full bounded redacted stdout/stderr, outcome, duration, reason and runtime provenance. Provenance includes requested/resolved digest, actual image/container IDs, source/policy hashes, controller start/end UTC and deadline, actual Docker State, inspected isolation, create argv, redacted transcript hashes, raw input byte counts, completeness and verified owned cleanup. Target code cannot edit these controller-owned observations. Exact controls and limits are in `phase2-runner.md`.

PASS requires the permitted command's matching result and integer zero exit, resolved reviewed image, matching source/policy, complete logs, actual target start and verified cleanup. No-op, unsupported stages, missing image/daemon, missing executable, output/memory limits and ambiguous observations cannot pass. An actual target nonzero exit is FAIL, including 125/126/127 when State proves target execution. Timeout is retained as a step outcome and reduces to INCONCLUSIVE. A valid observed failure is not hidden by later incomplete coverage. Coverage counts planned versus observed result slots; observed coverage is not the same as successful execution. BLOCKED before execution is not target FAIL.

Original observed text is retained after credential/terminal-control redaction within 65,536 raw bytes per stream. Larger output is explicitly incomplete and stopped. Raw credential-bearing streams are transient bounded memory only; Docker's persistent container log driver is disabled. Stored hashes cover the redacted transcripts. No model summary replaces logs, no model declares PASS, and unknown formats are not claimed to be universally secret-free.

The controller authenticates sanitized records with a private per-user HMAC-SHA256 key outside scanned repositories. The JSON includes its key ID, canonical payload SHA-256 and MAC. A fully written/fsynced temporary file is atomically linked to a unique JSON name without replacement. The key is never obtained from record input, source, logs or model output and is not shared with targets. Local HMAC verifies integrity under the trusted local key; it is not a public signature, third-party execution attestation or protection against a compromised host/key owner. `summary.json` from the fixture validator is a convenience index; its referenced authenticated records remain authoritative.

Passport validation checks local authentication, full current source/commit/policy/plan, legal finalized state/history, captured README commands and complete matching runtime results. Synthetic signed unit fixtures validate these checks only; real Docker cases and retained fixture records demonstrate actual execution. Clean docs-repair/retest and independent benchmark oracles remain later gates.

**Before final MVP extend:** clean-retest/patch identities and attempt budgets, provider opt-in/model metadata, independent agent A/B trial manifests and readable Markdown export. Durable intermediate/crashed-attempt journals and public-verifiable attestations remain unimplemented. Do not mutate finalized records, erase blocked/failed attempts, or treat workflow files as observed CI success.

**Success claim levels:** one observed offline `SMOKE_PASS` is not complete installation `ONBOARDING_PASS`, an independently observed `AGENT_COLD_START_PASS`, or generalized reproducibility. The latter is never claimed by this MVP.


## Phase 3 records

`repair-proposal-1` records preserve the authenticated baseline/source/policy/image, frozen operator oracle, bounded redacted provider request/response/error, requested/observed model, checkpoint/version, usage/cost basis and exact candidate README hash. They have no execution verdict; PROPOSED only means a permitted candidate awaits human review. `approval_digest` binds the sanitized complete proposal excluding its integrity/digest fields. A returned model field cannot confer approval or verified status.

`repair-recheck-1` binds that approval to fresh original and derived-candidate schema 1.2 runs, original source, independent oracle and unchanged non-README hashes/modes. Only the controller records VERIFIED after baseline FAIL, candidate PASS, matching image ID, distinct containers, cleanup and exact marker. Records use the existing private-key HMAC and exclusive atomic writer. Missing provider response means unknown usage/cost and an INCONCLUSIVE live attempt. Local authentication is not public attestation. A temporary candidate cannot create a passport for the untouched target; Phase 4 integration remains separate.
